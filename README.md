# 《守望先锋》回坑说明书 · 面向回流玩家的跨平台内容方案

**在线展示页：<https://martin-cell-blip.github.io/ow-content-playbook/>**

个人作品集项目，定位是内容研究与策划作品（内容尚未在平台发布，传播效果要发布后才有）。目标只有一个：让离开 3 个月以上的国服玩家在回归第一周**接上进度**——知道变了什么、能领什么、先玩什么、和谁玩。平台选 B 站（完整版）+ 小红书（切片与承接），抖音记录观察、本期不做（制作资源取舍，不是「不适合」）。

## 先看什么

1. [在线展示页](https://martin-cell-blip.github.io/ow-content-playbook/)（源文件 `site/index.html`，也可下载后双击打开）：先看选题一小红书版的七图文字样张（已排版，未发布），再看说明书本体（按离开时长分层）、3 选题 × 2 平台方案、三平台真实案例数据、验证方案（全部待验证）、事实与来源。离线可用、可打印。
2. `deliverables/01_项目说明_回坑说明书.docx` —— 方向比较、版本事实核验、平台分析、开源评审、验证方案、使用说明。
3. `deliverables/02_真实案例分析表.xlsx` —— 11 个工作表：B 站 215 条样本与 48 条热评、抖音 9 条 + 搜索列表（保存 13 条）、小红书 7 条 + 3 组搜索列表（「回坑」保存 19 条）、判断依据→设计、版本事实核验、观察限制。
4. `deliverables/03_跨平台内容样稿.docx` —— 6 份样稿（标题 / 封面 / 开头 / 脚本 / 素材来源与范围 / 互动 / 差异说明）+ 排期 + 文末七图完整文字；`deliverables/七图文字样张/01–07.png` 是同一文字的 1080×1440 自制排版卡。

## 数据从哪来、怎么重建

- `research/fetch_bilibili_cases.py`：B 站公开搜索接口与评论接口，匿名态、低频、只读；输出 `bilibili_cases.jsonl`、`bilibili_case_comments.jsonl`、`bilibili_fetch_log.json`。
- `research/manual_cases_2026-11-09.json`：抖音、小红书在本人登录态下的人工逐条观察（链接、发布日期、观察日期、可见互动数、评论摘录）。
- `research/sample_seven_cards.json`：七图文字（唯一文本源）；`research/make_cards.py` 用它导出 PNG。
- `research/build_data.py`：合并为 `deliverables/02_真实案例分析表.xlsx` 与 `site/data.json`。
- `site/build_site.py`：把 `data.json` 内联进 `index.html`。

重建：`python research/build_data.py && python site/build_site.py && python research/make_cards.py`。Word 文档由 Markdown 源经 pandoc 生成，源不随项目分发。

## 事实纪律

所有互动数字都是他人内容在平台上的公开可见数据，附链接、发布日期与观察日期（2026-11-09）。本项目没有发布任何内容，没有运营数据，不写「已运营」「已增长」。样稿是草稿，案例表是真实观测，验证方案的数值全部为空白或目标值并标「待验证」；中国赛区晋级队伍等易变事实标「待核验」，发布前必须替换。

口径上有三条固定做法：搜索列表只保存了部分条目（抖音 13 条、小红书「回坑」19 条），占比一律以保存条数为分母；版本事实逐条对照官网公告（免费皮肤的领取条件、比赛所用补丁均以官方公告为准）；验证按「发布前请目标玩家试读 → 发布后记录本账号基线」两步走，不预设阈值。

引用的他人内容仅作案例分析，版权归原作者所有；《守望先锋》及相关素材版权归暴雪娱乐与国服运营方所有，本项目为个人非商业研究作品。
